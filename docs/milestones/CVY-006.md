# CVY-006 — BullMQ queue + worker + idempotent handler skeleton · Milestone Report

**Date:** 2026-08-04 · **Roadmap day:** D4 · **Priority:** P0 · **Effort:** 6h → ~2h

## 1. Objective and Definition of Done

**Objective:** One durable job queue and a worker bootstrap with idempotent handlers, graceful
shutdown, and job deduplication. Durability is what lets a mid-run crash be recovered instead of
losing the demo.

| DoD criterion                                                        | Met?           | Evidence                                                                                                                                          |
| -------------------------------------------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| One queue; handlers keyed `(runId, itemIdx, phase)`, safe to re-run  | ✅             | `QUEUE_NAME = 'convoy'`; `HandlerKey`; four handlers behind one dispatcher                                                                        |
| `jobId = runId:phase:itemIdx`; duplicate enqueue does not double-run | ✅             | 3× enqueue → 1 waiting job; re-enqueue **after completion** → handler ran once                                                                    |
| IORedis `maxRetriesPerRequest: null`                                 | ✅             | `createConnection()`                                                                                                                              |
| ~~Concurrency 1 per run~~                                            | **superseded** | **DEC-002** — the card contradicts ARCHITECTURE §3/§4/§13/§15. Fan-out is now a named constant; a test observes peak in-flight = `EXECUTE_FANOUT` |
| `SIGTERM → worker.close()` drains in-flight jobs                     | ✅             | Handler mid-`await` completes before `close()` resolves; real bootstrap logs `drained cleanly`                                                    |
| Stalled-job re-pick (~30s) interaction documented                    | ✅             | **G-26** + `STALLED_INTERVAL_MS` / `MAX_STALLED_COUNT` set explicitly                                                                             |
| Idempotency-Key covers a re-picked job re-issuing a write            | ✅             | **DEC-003** — attempt fixed in `job.data`; test proves a retry gets a _different_ id and attempt                                                  |
| `AbortSignal` path for cooperative abort                             | ✅             | `HandlerContext.signal`; test asserts a handler observes the abort                                                                                |
| Convoy retries only its own faults                                   | ✅             | `JOB_ATTEMPTS` + jittered backoff; `enqueueRetry` documented as Convoy-side only                                                                  |

## 8. Decisions recorded

  at handler runtime.
