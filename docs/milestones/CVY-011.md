# CVY-011 — Critic agent + simulate veto + corroboration · Milestone Report

**Date:** 2026-08-05 · **Roadmap day:** D7 · **Priority:** P0 · **Effort:** est 10h

## 1. Objective and Definition of Done

**Objective:** a second, separately-prompted LLM that judges each action's justification against its
evidence, grounded by an external verifier — KeeperHub's real `simulate:true` dry run. The veto costs
zero gas: no signing, no broadcast, no audit row.

**What the second model buys, stated precisely.** The simulator answers "does this revert against
current chain state". Funding 500 USDC where the evidence names 250 simulates perfectly and is still
wrong. That gap is the entire justification for spending a model call here, and item 7 of the fixture
is exactly that case.

### 4c. One false veto, found and fixed — G-34

The **first** live measurement produced 5/5 invalid vetoed and **1 false veto**: item 3,
`fund(75000000)` against evidence reading "an additional 75.000000 USDC".

> quote: "additional 75.000000 USDC"
> reason: "The evidence indicates a 75 USDC top-up, but the action funds 75,000,000 units."

A base-units confusion. USDC has 6 decimals, so `75000000` **is** 75.000000 USDC — the same amount
written twice. The model had not been told the convention, so "does the amount match" was
unanswerable and it guessed; it happened to guess right on item 0 and wrong on item 3.

The fix is a fact the Critic legitimately needs, added to the fixed instruction and naming **no
fixture amount**: base-unit integers, a factor of exactly 1,000,000 is the convention rather than a
discrepancy, convert before comparing. It makes item 7 **sharper**, not weaker — 500.000000 ≠
250.000000 after conversion. Re-measured: **0 false vetoes**, and 5/5 invalid still caught.

That is the eval doing its job. The fixture was authored before the prompt was tuned, and the tuning
was to supply missing domain information, not to teach the model the answers.

### 4d. Provider reality

The first two live attempts lost 7 of 10 and 8 of 10 Critic calls to upstream 429s and timeouts —
the same wall CVY-010 hit. Three harness changes, none of which touch the measurement:

- The eval raises the LLM timeout to 60s **unless the operator set one in the shell**. The 8s value
  in `.env` is a production budget — CRITIQUING sits in the demo's tightest beat — and timing out a
  free-tier provider that answers in 20s records "the Critic missed this" for a latency fact about
  the tier rather than a quality fact about the model.
- Pacing raised to 4s between items; transport retry to 4 attempts with longer backoff.
- Transport failures are retried; **a response never is.** A malformed response goes to the single
  repair pass, which is the thing being measured.

`pnpm run eval:critic:replay` reproduces the committed measurement exactly — including the simulate
answers — with no credential and no spend. Verified.

## 5. Where the corroboration override actually lives

Two places, deliberately, and they agree:

- **`corroborate.ts`** implements the full table and is unit-tested directly, including the case the
  worker cannot reach.
- **`critiqueItem`** makes the override *structural*: the simulate runs first, and an item the
  simulator rejects returns **before the model is consulted at all**. Same outcome, no tokens spent
  asking about a call that cannot succeed.

Order of authority, top to bottom — each layer can only ADD a veto:

```
whitelist  →  simulator  →  arithmetic  →  Critic
```

A thrown Critic is **not** a veto. The port reaches a network; if it fails, the item keeps the
deterministic gate's verdict and the run records `criticConsulted:false`. Vetoing on an exception
would make a provider outage look like a batch full of bad items — the most expensive way to be wrong
here, and the documented fallback (simulator-only gate, Critic demoted to advisory) is precisely this
path.

## 6. The re-plan cycle

Capped by a constant, not a convention: `MAX_REPLAN_CYCLES = 1`. A test asserts the port is called
exactly once even when it keeps asking for another cycle.

An item still vetoed after its one re-plan becomes `FAILED`, with the closed-enum `veto_reason`
retained on the row, and the run seals `SEALED_PARTIAL`. An item the re-plan **did not ask to
revisit** stays `VETOED` rather than `FAILED` — it was never re-planned, so calling it "persistently
vetoed" would overstate what was tried.

With no `replan` port wired there is no cycle at all and a veto is final on the first pass, which is
the pre-CVY-011 behaviour unchanged.

## 7. Anti-injection

The same four defences as the Planner, because the threat is the same, and the same honest ranking —
only two of them are structural:

1. fixed system instruction, no interpolation (asserted by test)
2. token-delimited fencing the evidence cannot forge (asserted by test)
3. **the output schema has no address, target or calldata field** — an injected target is
   inexpressible, not merely rejected
4. **the whitelist** — a non-whitelisted target is vetoed ahead of every other check, and the model
   is not consulted about it

Evidence that instructs the Critic to approve or veto is itself a finding: the instruction says to
VETO with `evidence_mismatch`, quoting the attempt.

## 10. What this milestone did not do

- **The Critic is not wired into the deployed worker's default path.** It is an injected port
  (`OrchestratorDeps.critic`), supplied by whoever composes a run — the same boundary as the Planner
  (D-030), and for the same compile-level reason. `runBatch` with no port is the documented
  simulator-only fallback, and it reports `criticConsulted:false` rather than implying a judgement.
- **The re-plan port has no production caller yet.** It is exercised by six tests against the real
  database, including the bounded-loop assertion; the Planner-backed implementation belongs with the
  UI's re-plan affordance.
- **The override table was not exercised live**, because the model and the simulator never disagreed
  in this measurement. Covered by unit tests, and reported as such in §4a rather than left to look
  like a live result.
