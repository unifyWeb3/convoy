### Is the dump deterministic?

If the fixtures were not reproducible, "dumped, not hand-written" would be unverifiable — you could
never tell a regenerated file from an edited one.

```
$ md5sum tests/fixtures/payloadHash.fixtures.json
ace5d8dad690ee5daa1b1e4c2b92cb27
$ forge script script/DumpPayloadHashFixtures.s.sol && md5sum tests/fixtures/payloadHash.fixtures.json
ace5d8dad690ee5daa1b1e4c2b92cb27
$ git diff --stat tests/fixtures/
(no output)
```

### Is the parity test falsifiable?

A green parity suite is worth nothing if a broken encoder would also make it green. Mutating
`payloadHash()` to hash `BigInt(idx) + 1n`:

```
$ pnpm --filter @convoy/kh-client test
 Test Files  1 failed (1)
      Tests  26 failed | 21 passed (47)
```

26 of 47 fail. Mutation reverted. (The 21 that still pass are the structural checks and the
`encodeArgs`-only assertions, which do not involve `idx` — as expected.)

### Can the loosened key guard still catch a real violation?

G-15 added `--exclude-dir` to three guards. A guard that has been loosened and not re-tested is a
guard nobody has checked. Dropping `const k = process.env.PRIVATE_KEY;` into
`services/worker/src/_guardprobe.ts` — a directory the guard is supposed to police:

```
$ # guard 3, with the probe file present
services/worker/src/_guardprobe.ts        <- caught
$ rm services/worker/src/_guardprobe.ts
$ # guard 3, probe removed
(clean)
```

The exclusion is narrow enough: it skips generated output and still fails on a real key reference in
committed source. Probe removed; `git status` clean.

G-15 deserves emphasis: **the guards are the mechanism that makes "Convoy never holds a private key"
a claim rather than an aspiration**, and they are mirrored into `.convoy/checklists/review.md`
precisely so a human can paste them into a terminal. A guard that goes red on a correct repository is
one reviewers learn to skip — which is how the claim would quietly stop being enforced. CI itself was
never wrong.

**No new gap was needed for the encoding itself.** The documented fallback
(`keccak256(abi.encode(target, keccak256(bytes(fn)), keccak256(args), idx))`) was **not** used: the
frozen A4 encoding matched on the first attempt across every fixture, including the dynamic-type
cases the card flagged as medium risk.

## 8. Decisions recorded

- `D-012` — fixtures carry `argTypes` + `argValues`, not just precomputed `args` bytes, so
  TypeScript re-encodes independently. A fixture carrying only `args` would prove viem can hash a
  byte string, which was never in doubt; the risk is in the argument encoding.
- `D-013` — `fs_permissions` grants `write` to exactly one directory, not `read-write` on `./`.
- `D-014` — the generated fixture file is `.prettierignore`d, so formatting cannot fight the dump.
- `D-015` — the CI grep-guards exclude build output (see G-15).
