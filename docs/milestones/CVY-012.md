## Outcome

CVY-012 now exports a replayable, sha256-stamped JSON artifact with one reconciliation row per item
and one column for each independent source:

1. KeeperHub direct-execution status, refreshed from each persisted execution ID.
2. ConvoyRegistry events and current storage, read through viem from the dedicated Base Sepolia RPC.
3. Convoy's ledger: run, items, attempts and append-only events.

Rows are green only when every applicable comparison agrees. A divergence stays amber with named
checks; no fallback value is smoothed into green. Vetoed/skipped items can correctly be green when
the ledger records the terminal state and both external sources confirm that no execution or
commitment exists.

## Reconciliation rules

Per item, the exporter compares:

- KeeperHub status and transaction hash against every COMMIT/EXECUTE attempt in the ledger.
- The registry `ActionCommitted` event transaction and payload hash against KeeperHub and ledger.
- Registry `committed`/`payloadHash` storage against the event and local payload commitment.
- A `LANDED` ledger claim against a completed KeeperHub execution with a non-null hash.
- Expected absence for items that never reached COMMIT.

At run level it checks exactly one `RunOpened`, operator equality between the event and registry
storage, open/seal transaction hashes against ledger events, sealed state, and committed counts.

G-24 is mitigated structurally: receipt `to` and `from` are never reconciliation keys. Logs are
filtered by the emitting registry address, and `RunOpened.operator` is checked against storage.

## Stable export and cache

Per D-035, only terminal runs may be exported. The first export builds the live snapshot and upserts
the frozen JSON plus its 32-byte digest into `manifests`. Re-export returns the cached row, so a demo
still renders if KeeperHub or the RPC is unavailable.

The document stamp is computed over recursively key-sorted JSON, excluding only the `sha256` field.
On cache reads the hash is recomputed and compared with both the JSON field and the bytea column.
The export includes `runEthUsd`, gas consumed, payment spend, evidence, target/function/args,
payload hashes, plan, dependencies, attempts and events.
