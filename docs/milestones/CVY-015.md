# CVY-015 — Idempotency, Crash Resume, and Kill-Worker Proof

## Outcome

The production worker path now reconciles persisted KeeperHub executions before acting. An attempt
row is prepared before a write, the returned execution ID is persisted immediately, and recovery
polls that ID. If a process dies before the ID is recorded, the same persisted attempt number and
phase-folded idempotency key are replayed. No nonce is set and no private key enters Convoy.

The BullMQ phase handlers and `POST /api/runs` now use the existing `runBatch`/orchestrator path.
The API accepts only an existing persisted run ID and enqueues the deduplicated plan job. No second
orchestrator or unsupported product capability was introduced.

  `killworker.noDuplicateTx.test.ts`.

- `@convoy/web`: 84 tests passed.
- Package typechecks, scripts typecheck, lint, build, `git diff --check`, and the four CI invariant

The deterministic kill/restart proof uses a transport that throws during the first EXECUTE poll,
then resumes from the persisted execution ID. It proves one target broadcast, one transaction hash,
and one `ITEM_LANDED` event; the already-committed path is not resubmitted.

## Live Acceptance

The real Base Sepolia acceptance was not performed. `KEEPERHUB_API_KEY`, `BASE_RPC_URL`,
`CONVOY_REGISTRY_ADDR`, and related runtime configuration were not available to the worker process
for a fresh fanout-1 run. Consequently there is no real run ID, execution ID, transaction hash, or
KeeperHub broadcast count to report, and the duplicate-hash SQL query was not run against a live
Convoy database. This is reported as a blocker, not replaced with fabricated evidence.

## Scope Review

No UI, SSE behavior, manifest reconciliation, contracts, KeeperHub capabilities, nonce handling,
private-key handling, execution semantics, or frozen reports were modified. No fake retry, staged
failure, gas spike, or transaction hash was introduced.
