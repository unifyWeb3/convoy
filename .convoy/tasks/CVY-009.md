# CVY-009 — SSE timeline UI + audit drawer + replay-on-refresh

**Roadmap:** D9 · **Priority:** P0 · **Complexity:** M · **Risk:** Medium

## Objective

A live, GitHub-Actions-style execution timeline that streams over SSE and **survives a refresh** by
replaying from the database. The timeline is one of the two things that must never be cut — it is
the demo.

## Files expected

```
apps/web/app/api/runs/[id]/stream/route.ts
apps/web/app/runs/[id]/_components/{Timeline,AuditDrawer}.tsx
apps/web/lib/events.ts
apps/web/test/{api.stream.replay,timeline.render}.test.tsx
apps/web/e2e/refresh.replay.spec.ts
```

## Dependencies

CVY-005, CVY-008. **Blocks:** CVY-012, CVY-013.

## Acceptance criteria

- The stream route uses a `ReadableStream` with `export const dynamic = "force-dynamic"` and sets
  the `X-Accel-Buffering: no` header — reverse proxies buffer responses by default and would break
  streaming.
- **SSE replay semantics** (blueprint A6): the SSE event id **is** `events.id` (bigserial). The
  client sends `Last-Event-ID`; the route replays `events WHERE id > :lastId ORDER BY id`, then
  tails live. A mid-run refresh loses nothing.
- One timeline row per item, showing the state chips:
  `PLANNED → SIMULATED → (VETOED | COMMITTED → SUBMITTED → LANDED)`.
- Retry attempts **stack visibly** (attempt 1 → transient code → attempt 2 → LANDED). Gas chips show
  real numbers.
- Vetoed items are greyed with their decoded `revertReason` and a "0 gas" badge. Failed items are
  red with their run error code.
- The audit drawer shows, per item: the Planner's reason, the Critic's verdict with the simulate
  output (`wouldRevert`, `revertReason`, `gasEstimate`), every attempt with its transaction hash
  linked to `transactionLink`, and the corresponding ConvoyRegistry event.
- Every transaction hash links to Basescan and is click-through verifiable.

## Fallback

Poll `GET /api/runs/:id` every 2 seconds. Functionally equivalent, less impressive; record the
downgrade in `docs/KNOWN_GAPS.md`.

## Rollback

Revert the UI. The worker and the event log are unaffected.
