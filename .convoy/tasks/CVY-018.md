# CVY-018 — Telegram notifications

**Roadmap:** D13 · **Priority:** **P2 (only if time remains)** · **Complexity:** S · **Risk:** Low

## Objective

Send one notification when a run seals, using KeeperHub's Telegram notification node. Cosmetic by
design — this is the first thing to skip and it maps to no demo second.

## Files expected

```
services/worker/src/notify.ts
docs/DEPLOYMENT.md        (TELEGRAM_BOT_TOKEN documented as optional)
```

## Dependencies

CVY-008.

## Acceptance criteria

- A single notification on `RUN_SEALED` / `RUN_SEALED_PARTIAL` containing the run id, the counts of
  landed / vetoed / failed / skipped items, the budget consumed, and the manifest link.
- `TELEGRAM_BOT_TOKEN` is **optional**. When it is unset, notifications are skipped silently and
  nothing else changes — a missing token must never fail a run.
- Notifications are strictly out of band: they never gate, delay, or alter a state transition.

## Verification steps

```bash
pnpm --filter @convoy/worker test
# manual: seal a run with the token set → one message arrives
# manual: seal a run with the token unset → run completes normally, no error
```

## Fallback

**Omit entirely.** This is the correct outcome if anything else needs the time.

## Rollback

Revert; nothing depends on it.

## Effort

**2h.**

## Deliverables

An optional, non-blocking run-sealed notification — or a documented decision to omit it.
