# CVY-006 — BullMQ queue + worker + idempotent handler skeleton

**Roadmap:** D4 · **Priority:** P0 · **Complexity:** M · **Risk:** Medium

## Objective

One durable job queue and a worker bootstrap with idempotent handlers, graceful shutdown, and job
deduplication. Durability is what lets a mid-run crash be recovered instead of losing the demo.

## Files expected

```
services/worker/src/index.ts            (bootstrap, signal handling)
services/worker/src/queue.ts            (queue + connection + jobId scheme)
services/worker/src/handlers/{plan,critique,execute,seal}.ts   (skeletons, keyed and idempotent)
services/worker/test/{queue.dedupeJobId,worker.gracefulShutdown}.test.ts
```

## Dependencies

CVY-005. **Blocks:** CVY-008.

## Acceptance criteria

- **One** queue. Handlers are keyed `(runId, itemIdx, phase)` and are safe to re-run.
- `jobId = runId:phase:itemIdx` so a duplicate enqueue does **not** double-run.
- IORedis configured with `maxRetriesPerRequest: null` (required by BullMQ).
- Concurrency **1 per run** — submissions serialize against the single org wallet, which is exactly
  the contention KeeperHub resolves.
- `SIGTERM → worker.close()`: the worker stops accepting new jobs and waits for in-flight jobs to
  finish or fail. Note that stalled jobs are re-picked after roughly 30s by default.
- An `AbortSignal` path exists for cooperative run abort.
- Convoy retries **only its own faults** (LLM timeout, DB blip, network) with jittered backoff.
  Onchain retries belong to KeeperHub and are only observed.

## Verification steps

```bash
pnpm --filter @convoy/worker test        # dedupe + graceful shutdown
pnpm --filter @convoy/worker typecheck
pnpm --filter @convoy/worker build
# manual: enqueue → handler runs → completes; enqueue the same jobId twice → runs once
# manual: send SIGTERM mid-job → job drains, process exits cleanly
```

## Fallback

If Redis is unavailable during the demo, fall back to a single in-process consumer. Durability is
lost, so record the downgrade in `docs/KNOWN_GAPS.md` before relying on it.

## Rollback

Revert the package to its CVY-000 scaffold. Nothing depends on it until CVY-008.
