# CVY-014 — Human approval gate

**Roadmap:** D8 · **Priority:** P1 · **Complexity:** S · **Risk:** Low

## Objective

A cooperative pause before the `EXECUTING` phase, so an operator can review the plan and the Critic's
verdicts before any spend occurs.

## Files expected

```
apps/web/app/api/runs/[id]/approve/route.ts
apps/web/app/api/runs/[id]/abort/route.ts
services/worker/src/handlers/approve.ts
apps/web/test/api.runs.approve.test.ts
```

## Dependencies

CVY-008.

## Acceptance criteria

- The run pauses at the boundary between `CRITIQUING` and `EXECUTING` when the approval gate is
  enabled.
- `POST /api/runs/:id/approve` resumes the run; the transition is transactional and emits exactly one
  `events` row.
- `POST /api/runs/:id/abort` performs a **cooperative** abort — in-flight KeeperHub calls are not
  killed mid-flight; the run stops accepting new work and reaches `ABORTED` cleanly.
- The pause is durable: a worker restart while paused does not lose the pause or auto-resume.
- Approval is an operator action, never an agent action.

## Verification steps

```bash
pnpm --filter @convoy/web test
# manual: start a run with the gate on → it pauses → POST /approve → it resumes and lands items
# manual: start a run → POST /abort → it reaches ABORTED with no orphaned in-flight execution
```

## Fallback

Cut #4: auto-approve. The gate is skipped and the run proceeds straight from `CRITIQUING` to
`EXECUTING`. Disclose the cut in the honesty table.

## Rollback

Revert; the state machine proceeds automatically as it did before.

## Effort

**3h.**

## Deliverables

A durable pause/resume gate and a cooperative abort path.
