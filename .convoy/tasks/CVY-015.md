# CVY-015 — Idempotency + crash-resume + kill-worker test

**Roadmap:** D12 · **Priority:** P0 · **Complexity:** L · **Risk:** **HIGH** (reliability is weighted heavily)

## Objective

Kill the worker mid-execution and resume with **no duplicate transaction**. This is the genuinely
hard part of the system: an idempotent, crash-resumable state machine over an async external
executor with real nonce contention.

## Fallback

**None. This milestone is never cut.**

## Files expected

```
services/worker/src/reconcile.ts
packages/kh-client/src/idempotency.ts        (hardened)
services/worker/test/{reconcile.crashResume,killworker.noDuplicateTx}.test.ts
```

## Dependencies

CVY-006, CVY-008.

## Acceptance criteria

- Every write carries `Idempotency-Key: <runId>:<idx>:<attempt>` — per-org, replayable for 24 hours.
  Simulate calls are exempt.
- **Reconcile before acting.** On startup, every non-terminal item is re-derived from KeeperHub
  status before any new call is made:

  | Observed                                         | Action                                      |
  | ------------------------------------------------ | ------------------------------------------- |
  | `completed` + non-null `transactionHash`         | → `LANDED`                                  |
  | `failed` + coded transient                       | → `RETRYING` (under cap) else `FAILED`      |
  | `failed` + config-revert (full message, no code) | → `FAILED`, **never retried**               |
  | `pending` / `running`                            | keep polling, honour `X-Poll-Interval-Hint` |
  | no `execution_id` recorded                       | re-issue with the **same** idempotency key  |

- `409 idempotency_in_progress` → back off and retry the same key.
  `409 idempotency_conflict` → a Convoy bug; fail the item and record a gap.
- **Kill-worker test:** `SIGKILL` during the EXECUTE phase, then resume → the same `execution_id`
  and the same `transactionHash`; **no second broadcast**.
- Defence in depth: the onchain `committed[runId][idx]` one-shot plus `DupIndex()` makes a
  double-commit impossible even if everything above fails.
- Recovery never sets a nonce and never invents a transaction hash.

## Verification steps

```bash
pnpm --filter @convoy/worker test         # reconcile.crashResume + killworker.noDuplicateTx
# manual: start a run, SIGKILL the worker mid-EXECUTE, restart, confirm identical hashes
psql "$DATABASE_URL" -c "select tx_hash, count(*) from attempts where tx_hash is not null group by 1 having count(*)>1;"
# ^ must return zero rows
```

## Rollback

Revert only if it does not reintroduce a double-broadcast risk. If reverted, the run must not be
restartable at all — a non-resumable run is safer than a double-broadcasting one.
